# Right-arm camera control

Press **C** or click **Camera** while playing and grant camera access in the browser. Face the lens with both shoulders, your right elbow and your right wrist in view. Lift the arm sideways to raise the avatar’s right arm. Bend your elbow in the plane of the picture to bend its elbow. The small camera preview behaves like a mirror. Press **C** again or choose **Stop camera** to end capture.

The motion tracker estimates landmarks in a single camera image. It uses shoulder orientation, upper-arm direction and the angle at the elbow to drive the existing right-arm rig in degrees. The shoulder stays in the lateral plane. Closed fingers, wrist rotation, forward reach and depth are outside this control. Occlusion, foreshortening and a side or back view can break tracking. When confidence falls, camera updates cease and the game retains the last drawn pose. Ordinary controls can move the arm again.

The browser asks for video only. Frames pass to a dedicated worker on the same device. The worker returns three game joint values and releases the frame. Nothing records or uploads the video. The model, JavaScript and WebAssembly load from the local preview after opt-in. Stopping, closing the game or hiding the page releases the camera tracks and terminates the worker. Use the bundled localhost launcher or a secure HTTPS origin that permits camera access. This preview needs video capture, Web Workers, OffscreenCanvas, ImageBitmap, WebAssembly and WebGL support.

## Verification

From the game directory, run `node --test scene/src/camera/tests/rig.test.mjs`. The browser check requires Chromium, Playwright and FFmpeg. Run `node scene/src/camera/tests/browser.mjs`. To use existing installations, set `NS_PLAYWRIGHT_MODULE` to the Playwright module path, `NS_CHROMIUM` to the Chromium executable and optionally `NS_ANGLE` to a supported graphics backend.

The browser test uses Chromium’s virtual video device with exercise frames and an empty frame. It checks the local model response, tracking loss, permission denial, a late permission grant after cancellation, unsupported-browser handling and track cleanup. It then opens the regular game launcher, presses C and samples the angles actually drawn by the game. It also checks that the feature made only same-origin GET requests. The runner never opens a physical camera.

The worker uses CPU inference on one frame at a time, at most 640 pixels along the longer dimension. There is a 90 ms minimum gap between an inference result and the next frame. Inference and temporary buffers are kept off the game's main thread. Chromium and the MediaPipe runtime control thread placement, WebGL texture handling and SIMD selection. This implementation has no measured inference-speed advantage over another backend. Native camera performance, other operating systems and other browsers still need testing.
